# Checkpoint 01: LOTM Ritual Bar (QML-First)

## Session Start

- Goal: implement a first visible LOTM ritual bar checkpoint for Hyprland without breaking existing workflow.
- Agent profile: Rice Architect.
- Skill recipe: Theme Switching Architecture.
- Tiny deliverable: render one top bar with left pathways, center ritual clock plus window context, right placeholders.

## Scope

Include:

- Pathway-based workspace display as the primary visual.
- Active pathway highlight from Hyprland workspace state.
- Ritual clock (simple first pass).
- Active window context text (subtle secondary role).

Exclude:

- Systray integration.
- Notification center integration.
- Launcher and pathway wheel.
- Heavy custom animation framework.

## Runtime Boundaries

Nix responsibilities:

- Enable and deploy Quickshell runtime files.
- Generate runtime data contract in `.config/quickshell/generated/theme.json`.
- Gate activation with `rice.enable`.

Quickshell responsibilities:

- Read runtime JSON.
- Bind Hyprland state to UI.
- Apply basic transitions and visual behavior.

## Data Contract v1 (Generated by Nix)

`theme.json` minimum fields:

- `schemaVersion`: `1`
- `theme`: active theme id
- `assets.shared`: absolute path string
- `assets.active`: active theme assets object
- `assets.themes.lotm.pathwaysDir`: absolute path string
- `lotm.pathways`: ordered list of pathway metadata for visible workspaces

Example shape:

```json
{
  "schemaVersion": 1,
  "theme": "lotm",
  "assets": {
    "shared": "/.../modules/rice/shared/assets",
    "active": {
      "root": "/.../modules/rice/themes/lotm/assets",
      "pathwaysDir": "/.../modules/rice/themes/lotm/assets/pathways"
    },
    "themes": {
      "lotm": {
        "root": "/.../modules/rice/themes/lotm/assets",
        "pathwaysDir": "/.../modules/rice/themes/lotm/assets/pathways"
      }
    }
  },
  "lotm": {
    "pathways": [
      { "workspace": 1, "id": "fool", "label": "Fool", "icon": "fool.svg" },
      { "workspace": 2, "id": "door", "label": "Door", "icon": "door.svg" },
      { "workspace": 3, "id": "error", "label": "Error", "icon": "error.svg" }
    ]
  }
}
```

## Implementation Checklist

1. Add or extend `modules/programs/quickshell/default.nix` to deploy `ui/` into `.config/quickshell` only when `osConfig.rice.enable` is true.
2. Keep Quickshell package/install concerns in Home Manager and avoid UI logic in Nix.
3. Add guarded startup in `modules/services/hyprland.nix` via `exec-once` for Quickshell when `rice.enable` is true.
4. Extend runtime JSON generation in `modules/rice.nix` with `schemaVersion` and a minimal `lotm.pathways` list.
5. Create `ThemeLoader.qml` to load and parse `.config/quickshell/generated/theme.json` safely with fallback defaults.
6. Create `HyprlandState.qml` to expose active workspace and focused window context.
7. Implement `Pathways.qml` using workspace mapping from runtime JSON and subtle active-state transitions.
8. Implement `RitualClock.qml` (hours and minutes only, stable update interval).
9. Implement `WindowContext.qml` with title cleanup and max length clipping.
10. Implement `SystemPlaceholders.qml` with minimal static placeholders for later replacement.
11. Compose all components in `Bar.qml` using left/center/right sections.
12. Mount `Bar.qml` from `shell.qml` on top layer.

## Verification Checklist

1. `nix flake check --no-build` passes after staging.
2. With `rice.enable = false`, Quickshell is not launched and current behavior remains unchanged.
3. With `rice.enable = true`, Quickshell launches and renders one top bar.
4. Active workspace changes update pathway highlight correctly.
5. Focus changes update window context text with no obvious flicker.
6. Ritual clock updates once per minute and keeps stable formatting.
7. Missing or malformed `theme.json` does not crash shell (fallback behavior works).
